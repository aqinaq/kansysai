\section{Purpose}

This document compares existing task-management systems against one consistent set of criteria in order to answer two questions:
\begin{enumerate}
  \item Which parts of the proposed voice-to-Kanban workflow already exist in other products?
  \item Which combination of capabilities is still missing, and therefore justifies building our system?
\end{enumerate}

Every claim about another product is linked to a source (Section~\ref{sec:refs}). Where a feature is not described in the sources we reviewed, the table says ``Not found'' rather than ``No'', because absence from documentation does not prove that the feature does not exist. Sources were checked on 21 October 2026; AI features in these products change quickly.

\textbf{Screened but excluded.} The team's initial review (DEMO-21, first draft) also covered \textit{Vibe Kanban}, \textit{Formic} and \textit{KaibanJS}. They were excluded from the main comparison because they target software developers and coding agents (running agents on code, decomposing coding goals, or a developer framework) rather than general teams. Formic's decomposition of a goal into 3--8 subtasks remains a useful reference for our multi-task extraction.

\section{Gap Analysis and Justification}

Each capability of our system already exists \emph{somewhere}: Todoist extracts several tasks from speech with a preview, ClickUp turns meeting action items into tasks, Jira's Rovo updates work items from chat. The gap is in the \textbf{combination} and in the \textbf{local context}:

\begin{enumerate}
  \item \textbf{No reviewed system covers C2--C6 together.} Todoist creates tasks by voice but cannot change existing ones; Jira changes existing items but has no voice input; ClickUp converts meetings into tasks but does not describe a review step.
  \item \textbf{Kazakh and mixed Kazakh--Russian speech (C7) is not supported or not documented} in any of the five systems. Todoist explicitly lists Russian but not Kazakh.
  \item \textbf{Voice data stays in the cloud (C8)} in all mainstream systems. Our design processes voice on our own server and offers a local LLM mode.
  \item \textbf{Safety rule for team data.} Only Todoist documents a review step, and only for new personal tasks. Our system requires confirmation for every change (create, update, status, assignment) and checks the user's permissions.
\end{enumerate}

\textbf{Conclusion.} The proposed system is justified not by a single new feature, but by bringing together voice and text commands for the full task life cycle on a team Kanban board, with mandatory confirmation, answers grounded in real project data, and support for Kazakh, Russian, English and mixed speech.

\subsection{Ideas Adopted from Existing Systems}

\begin{itemize}
  \item From \textbf{Todoist Ramble}: live preview while the user speaks; voice corrections such as ``remove that''; pausing between items to separate tasks.
  \item From \textbf{ClickUp AI Notetaker}: meeting recording $\rightarrow$ action items $\rightarrow$ task drafts with assignees.
  \item From \textbf{Jira Rovo}: breaking larger work into smaller tasks; summaries with status, blockers and next steps.
  \item From \textbf{Formic} (excluded tool): decomposition of a goal into a bounded number of subtasks.
\end{itemize}

% =====================================================
\section{Limitations of This Comparison}

\begin{itemize}
  \item Most sources are vendor pages and documentation; they describe intended functionality, not measured quality. Third-party reviews are used only for pricing.
  \item The systems were not tested hands-on with Kazakh or mixed speech. ``Not found'' means not documented, not proven absent.
  \item AI features and prices change frequently; the comparison reflects sources checked on 21 October 2026 and should be re-checked before the final defence.
\end{itemize}
